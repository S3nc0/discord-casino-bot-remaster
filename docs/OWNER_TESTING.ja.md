# オーナー向け動作確認チェックリスト

[English](OWNER_TESTING.md) | **日本語**

[オーナー向けセットアップガイド](OWNER_SETUP.ja.md) を終えた直後と、アップデートを取り込むたびにこのチェックリストを上から確認してください。デスクトップとスマホの両方で正しく動くかを確かめられます。

> [!CAUTION]
> **機密情報は絶対に共有しないでください。** 不具合報告でスクリーンショットやログを送るときは、**Bot Token**（`DISCORD_TOKEN`）・**OAuth2 Client Secret**（`DISCORD_CLIENT_SECRET`）・**`SESSION_SECRET`**・`.env` ファイルを絶対に含めないでください。

---

## 1. テスト前の準備

1. **ターミナル 1**（`pnpm dev:server`）と **ターミナル 2**（トンネル）の両方が起動していることを確認します。
2. **クイックトンネル**（`pnpm dev:tunnel:quick`）を再起動した場合は、新しく出た `xxxx.trycloudflare.com` をコピーして **Developer Portal → 対象アプリ → Activities → URL Mappings** の `/api` を `xxxx.trycloudflare.com/api` に更新し、**Save Changes**（変更を保存）を押します。
3. Discord を再読み込みします。
   - **デスクトップ:** `Cmd+R`（macOS）または `Ctrl+R`（Windows/Linux）。
   - **スマホ:** Discord アプリを完全に閉じてから開き直します。

✅ **期待する結果:** 両方のターミナルがエラーで落ちずに動いており、Discord が最新の URL Mappings を読み込んでいます。
**うまくいかないとき:** [オーナー向けセットアップガイド — 手順 6・7](OWNER_SETUP.ja.md) を確認してください。

---

## 2. ヘルスチェック（疎通確認）

3 つ目のターミナルタブで、次の 3 つを順番に実行します（`<tunnel-host>` と `APP_ID` は自分の値に置き換え）。

1. Mac 上のサーバー単体:

   ```sh
   curl -i http://localhost:3001/api/health
   ```

2. Cloudflare トンネル経由:

   ```sh
   curl -i https://<tunnel-host>/api/health
   ```

3. Discord の URL Mapping 経由:

   ```sh
   curl -i https://APP_ID.discordsays.com/.proxy/api/health
   ```

✅ **期待する結果:** 3 つすべてで HTTP `200` と `{"status":"ok","db":"ok",...}` が返ってきます。
**うまくいかないとき:**
- 1 つ目が失敗 → ターミナル 1（`pnpm dev:server`）が止まっているかエラーが出ています。
- 2 つ目が失敗 → ターミナル 2（トンネル）が止まっているか、`<tunnel-host>` が古いままです。
- 3 つ目が失敗 → **Activities → URL Mappings** の `/api` が `<tunnel-host>/api`（`https://` なし・末尾スラッシュなし）になっていません。

## 3. デスクトップでの起動

1. デスクトップ版 Discord のテストサーバーで Activity を起動します。
   - **ボイスチャンネル:** ボイスチャンネルに参加 → **Activities**（ロケットアイコン）→ 対象アプリを選択。
   - **テキストチャンネル:** メッセージ欄横の **Apps**（アプリ）ボタン → 対象アプリ → **Launch**（起動）（または `/launch`）。
2. 初回起動時は **Authorize**（認証）画面が出るので **Authorize** をクリックします。

✅ **期待する結果:** **Home**（ホーム）画面が開き、残高（新規プレイヤーは **3,000 Pelica**）と接続ステータス（接続済み / OK）が表示されます。
**うまくいかないとき:** ターミナル 1 で `auth rejected: <reason>` の行を探し、[オーナー向けセットアップガイド — トラブルシューティング](OWNER_SETUP.ja.md) を確認してください。

---

## 4. スマホでの起動（iOS / Android）

1. スマホの Discord でテストサーバーのボイスチャンネル（またはテキストチャンネル）を開きます。
2. Activity を起動します。
   - **ボイスチャンネル:** ボイス操作パネルを開く → **Activities**（ロケットアイコン）→ 対象アプリを選択。
   - **テキストチャンネル:** **`+`** / **Apps** ボタン → 対象アプリ → **Launch**（起動）。
3. **縦画面（ポートレート）** で表示を確認し、スマホを横に向けて **横画面（ランドスケープ）** でも確認します。
4. 下部ナビゲーションバーの各タブをタップして切り替えます。

✅ **期待する結果:**
- OS 非対応エラーにならずに起動します。
- Discord 上部のバーやスマホ下部のホームバーに文字やボタンが隠れていません。
- 文字や残高がはっきり読めます。
- 縦画面・横画面のどちらでも下部ナビゲーションがスムーズに動きます。

**うまくいかないとき:**
- 「この OS では利用できません」と出た場合は、**Developer Portal → Activities → Settings → Supported Platforms** で **iOS** と **Android** にチェックを入れ（画面の向きはロックしない）、**Save Changes**（変更を保存）を押してスマホの Discord を完全に再起動してください。
- 表示崩れや文字切れがある場合は、スクリーンショットを撮って報告してください（手順 9）。

---

## 5. テーマ切り替え（ライト / ダーク）

1. Discord 側の外観を切り替えます: **User Settings**（ユーザー設定・歯車アイコン）→ **Appearance**（テーマ）→ **Light**（ライト）/ **Dark**（ダーク）。
2. Activity 内の **Settings**（設定）を開き、アプリ内のテーマ設定（ライト・ダーク・自動）を切り替えます。

> [!NOTE]
> Discord はライト / ダークの設定を Activity に伝えてくれません。そのため、アプリ内のテーマを **自動（Auto）** にしているときは、Discord ではなく **端末本体の** ライト / ダーク設定に連動する場合があります。

✅ **期待する結果:** アプリ内のライト・ダークがきれいに切り替わり、どの文字やボタンも読みやすいコントラストを保っています。
**うまくいかないとき:** 読みにくい画面とテーマ名をメモし、スクリーンショット付きで報告してください。

---

## 6. 言語切り替え（`EN ⇄ 日本語`）

1. Activity 内の **Settings**（設定）→ 言語設定を開きます。
2. **English** と **日本語** を何度か切り替えます。
3. **Auto**（自動）を選び、Discord クライアントの言語に合っているか確認します。
4. 各言語で設定を変更するなどして、トースト通知（画面下の一時メッセージ）も確認します。

✅ **期待する結果:** 見出し・下部ナビゲーション・トースト通知を含め、画面上のすべての文字が即座に切り替わります。**Auto** では Discord クライアントの言語に従います。
**うまくいかないとき:** 切り替わらなかった箇所をメモして報告してください。

---

## 7. サウンド・アニメーション設定の保存

1. Activity 内の **Settings**（設定）を開きます。
2. **サウンド** と **アニメーション** のオン / オフを変更します。
3. Activity を一度完全に閉じ、もう一度起動します。
4. ふたたび **Settings** を開いて確認します。

✅ **期待する結果:** 閉じて開き直したあとも、変更したサウンドとアニメーションの設定がそのまま残っています。
**うまくいかないとき:** ターミナル 1 に `/api/settings` 関連のエラーが出ていないか確認し、報告してください。

---

## 8. サーバーログの確認（ターミナル 1）

Activity を操作しながら **ターミナル 1** のログを確認します。

- **正常なログ（対応不要）:** 起動メッセージ、HTTP `200` の記録、および `proxy signature: present=absent`。
  - `proxy signature: present=absent` は **正常** です。この環境では Discord が Activity の通信に署名ヘッダーを付けないため、そのまま気にせず使って問題ありません。
- **異常なログ:** `auth rejected: <reason>` や予期しないエラー行。

✅ **期待する結果:** 通常の操作中に `auth rejected:` やエラー行が出ません。
**うまくいかないとき:** 表示された `<reason>` を [オーナー向けセットアップガイド — トラブルシューティング](OWNER_SETUP.ja.md) で調べてください。

---

## 9. 問題の報告方法

トラブルシューティングを見ても解決しないときは、次の 4 点をまとめて報告してください。

1. **どこで起きたか:** このチェックリストの何番で、何が起きたか。
2. **ターミナル 1 のログ行:** `auth rejected: <reason>` やエラー行そのまま（`.env` や機密キーは絶対に貼らないこと）。
3. **端末とスクリーンショット:** デスクトップ / iOS / Android の別と、個人情報や機密が写っていないスクリーンショット。
4. **再現手順:** 何をクリック・タップしたか 2〜3 行の箇条書き。

## 10. チャットコマンド（Wave 2）

先に [オーナー向けセットアップガイド — 手順 8](OWNER_SETUP.ja.md) を済ませておいてください。以前の Python 製ボットが止まっていて、`BOT_DISABLED=0`、サーバーが起動中で、`pnpm commands:deploy:guild` も実行済みの状態です。テストサーバーのテキストチャンネルで試します。数字を見比べられるよう、チャットの横で Activity も開いておくと便利です。コマンド名は英語で書き、日本語表示の Discord での名前をカッコ内に添えています。

- [ ] **残高が Activity と一致する。** `/ペリカ 残高`（`/pelica balance`）の残高が、Activity の **ホーム** 画面と同じ。
- [ ] **デイリー。** `/ペリカ デイリー`（`/pelica daily`）でデイリーを 1 回受け取れる。すぐもう一度実行すると「まだ受け取れません」という案内が出る。Activity の残高も同じように増えている。
- [ ] **送金。** `/ペリカ 送金`（`/pelica transfer`）で他のメンバー（または 2 つ目のテスト用アカウント）に少額を送る。送った側と受け取った側の残高が、同じ金額だけ動く。
- [ ] **カジノのゲーム。** `/カジノ スロット`（`/casino slots`）を少額のベットで遊ぶ。結果が表示され、勝ち負けの分だけ残高が変わる。
- [ ] **競馬の厩舎。** `/競馬 厩舎`（`/horse stable`）がエラーなく開く（馬がいなくても問題ありません）。
- [ ] **証券の注文。** `/証券 注文`（`/market order`）で少額の注文を出す。注文が受け付けられ、現金と保有の増減が想定どおり。
- [ ] **融資の提案。** `/貸付 提案`（`/loan offer`）を他のメンバーに出す。相手に提案が見え、相手が承諾するまでお金は動かない。
- [ ] **告知チャンネル。** `/運営 通知設定`（`/admin notifications`）で `チャンネル` にテスト用チャンネルを指定し、大当たり基準を低め（たとえば `1000`）にする。そのうえで基準以上の勝ちを出すと、そのチャンネルに大当たりの告知が投稿される。
- [ ] **オプトインの DM。** 通知の種類ごとに DM をオンにしてあれば、そのイベントが起きたときにボットから DM が届く。オンにしていなければ DM は届かない。
- [ ] **受信トレイ。** 同じイベントが、DM の設定にかかわらず Activity の受信トレイにも表示される。
- [ ] **言語。** Discord を日本語にするとコマンド名も返信も日本語、英語に戻すと英語になる。

✅ **期待する結果:** どのコマンドも数秒以内に返事があり、`アプリケーションが応答しませんでした` のような表示が出ず、チャットと Activity の残高がすべて一致します。
**うまくいかないとき:** 症状を [オーナー向けセットアップガイド — トラブルシューティング](OWNER_SETUP.ja.md) で探してください。載っていなければ報告してください（手順 9）。
