# Bitbloom テーマの再調整: 提案

ステータス: **ラウンド 2 を適用済みです。** これが唯一のテーマです。`design/bitbloom/tokens.json` と `tokens.css` にラウンド 2 の値（ダークとライト）が入り、`packages/ui` がコンポーネントの差分、ピクセルアート（`GameIcon`、`Skyline`、`Sparkle`）、`apps/web` のホームのヒーローとゲームのタイルと一緒に出荷しています。提案用のツールは移動しました。`design/bitbloom/build_tokens.py`（`design/bitbloom/proposal/archive/` にある元のパレットからトークンを作る）と `design/bitbloom/contrast_check.py` です。ラウンド 1 のファイルと 3 列のプレビューは削除しました。git の履歴に残っています。

**ラウンド 2 は 2026-11-22 にオーナーが承認しました。**

ラウンド 1 は落ち着いていましたが、灰色すぎました。ラウンド 2（下）は、オーナーのフィードバックに応えたものです。ムードのリファレンスに近づけ、緑、黄、青で明るくします。ラウンド 1 はもうツリーにありません。

## なぜやるのか

オーナーは、UI がきつすぎると感じています。スマホのスクリーンショットを見ると、原因は次のとおりです。緑がかった黒の上のまぶしいシアンの primary、選択中のナビ項目とトーナルボタンに使われている、明るい枠線付きの濃い茶色のブロック、すべての入れ物にある明るい 2px の枠線。たくさんの強い色が一度に目に入ります。

## ムードのリファレンスが行っていること（codedex.io のホーム、料金、コミュニティ）

- ほぼ黒の紺のページに、ひと段明るいカードと細い縁。文字は今も明るく、ページのコントラストは低くありません。
- ほとんどのページで、アクセントは 2 色だけ。平らな黄色の行動ボタンと、選択やリンクに使う空色です。料金ページには、強い紫のグラデーションと光彩が加わります。
- ぽってりしたボタン: 平らな塗り、2px の濃いふち、ピクセルフォントのラベル。2 番目のボタンは透明で、灰色の枠線です。
- ピクセルアートがあるのは、ヒーローのバナー、コースのサムネイル、小さなアバターです。ナビ、カード、フォームは平らで静かです。
- ピクセルフォントは見出しだけ、本文はすっきりしたサンセリフ、見出しの上には小さく字間をあけた大文字のラベル。
- セクションの間は広め。動きは小さく、タイプされる見出しときらめくスパークルです。

## ラウンド 2: 紺のベース、緑 / 黄 / 青、ピクセルアートを増やす

オーナーからの方向: リファレンスの雰囲気に近づけ、明るく鮮やかな色にする。緑、黄、青。

## コントラストの証明

`python3 design/bitbloom/contrast_check.py` は、出荷したトークンを解決し、1 つでも失敗があれば 1 で終了します。提案が承認されたときの出力は次のとおりです。

```
tokens.json: 396 checks, 0 failing
```

両方のテーマで、次を確かめます。`X` の上のすべての `on-X` と、`X-container` の上の `on-X-container` が 4.5 以上。6 つのサーフェスすべての上で、`on-surface` と `on-surface-variant` が 4.5 以上。6 つのサーフェスすべての上で、primary、secondary、tertiary、error、success、warning と 16 色すべての色相のアクセントを文字として使ったときに 4.5 以上。6 つのサーフェスすべての上で、`outline` と `focus-ring` が 3 以上。スナックバーと無効の文字が 4.5 以上。文字が薄められていないこと（`surface` の上で、`on-surface` が 10 以上、`on-surface-variant` が 5.5 以上）。`outline-variant` が `outline` より控えめで、それでも見える段になっていること（`surface` の上とカードの塗りの上で 1.3 以上）。隣り合うサーフェスの層が 1.04 以上離れていること。参考までに、同じルールを現在のトークンに当てると、3 件が引っかかります（ダークでのスライダーのトラックの枠線が 2.95:1 であること、そして両方のテーマで `outline-variant` が `outline` より控えめになっていないこと）。

## リスク

1. **ロールの意味が動く。** `secondary` はオレンジでしたが、静かなスレートか砂色になります。`tertiary` はバイオレットでしたが、金になります。`warning` は琥珀色でしたが、オレンジになります。採用する前に、`apps/web` のすべての使用箇所を確認してください。
2. **テストのルールを変える必要がある。** `packages/ui` とシェルのコントラストのテストは、`outline-variant` が 3:1 以上であることを求めていて、シェルはカードに `--bc: var(--outline)` を強制しています。採用すると、`outline-variant` は装飾用（1.5〜1.8:1）になり、シェルの上書きブロックはなくなります。装飾用の縁が、コントロールの唯一の手がかりになってはいけません。意味を持つものは `outline` に残します。
3. **`color-mix()`** をトーンのある縁に使っています（Chrome 111 以降、Safari 16.2 以降、Firefox 113 以降）。古い埋め込みの WebView では、その縁が消えます。採用前の対策は、明示的な `*-edge` トークンをあらかじめ計算しておくことです。
4. **金とオレンジ。** アクセントと警告は色相が近いです。バナーとタグには必ずアイコンと言葉が付くので、色だけの表示ではありませんが、十分に区別できて見えるかどうかは、オーナーが確認する必要があります。
5. **サーフェスは暗く、縁はやわらかく** なるのが狙いですが、日なたの暗いスマホ画面では、ライトテーマの 1.5:1 の縁がうすく感じられるかもしれません。その場合は `paper-variant-80` を 1 段上げます。
6. **実機では未確認。** このチェックが証明するのは比率であって、心地よさではありません。オーナーのスマホでの確認が本当のテストです。Discord 自身の上部バー（赤い Leave ボタン）は、こちらでは制御できません。
7. **ライトテーマの温かさ。** 画面によっては、クリーム色が黄色く見えることがあります。その場合の代替は、`surface` に `paper-97` を使うことです。
