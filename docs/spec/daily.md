## Rules & Exact Numbers

### 6-Hour JST Reset Slots
- Constants (`catalogs/economy.yaml:4-7`):
  - `DAILY_BASE = 1_000`
  - `DAILY_STREAK_BONUS = 100`
  - `DAILY_STREAK_CAP = 20` (caps `(streak - 1)` at `20` → max base payout `1,000 + 100 * 20 = 3,000` before multipliers)
  - `DAILY_SLOT_HOURS = 6` (4 claim slots per day: `00:00`, `06:00`, `12:00`, `18:00` in configured timezone, default JST `UTC+9`)
- Slot index formula (`cogs/economy/cog.py:55-57`):
  `slot = now.date().toordinal() * (24 // 6) + (now.hour // 6)` = `toordinal * 4 + hour // 6`.
  (If `slot` parameter is omitted at the repo layer, defaults to `today.toordinal()` — once per day.)
- Next slot timestamp (`cogs/economy/cog.py:60-64`):
  `midnight(now.date()) + timedelta(hours=(now.hour // 6 + 1) * 6)`.
- Eligibility check (`infra/db/wallet.py:126-133`):
  - If `last_slot is None and last is not None`: legacy migration fallback sets `last_slot = last.toordinal()`.
  - Rejected (`ok=False`) if `(last is not None and last > today)` (clock rollback protection) OR `(last_slot is not None and slot <= last_slot)`.

### Streak Calculation & Streak Guard
- Streak counts **calendar days**, NOT 6-hour slots (`infra/db/wallet.py:134-149`):
  - `last == today`: `streak = max(1, daily_streak)` (multiple claims on the same day keep the same streak day count).
  - `last == today - 1 day`: `streak = daily_streak + 1`.
  - Otherwise (`last is None` or gap >= 2 days):
    - Default `streak = 1`, `guarded = 0`.
    - `missed = (today - last).days - 1` if `last is not None` else `0`.
    - If `missed > 0 and daily_streak > 0`: attempts atomic decrement of `inventory` item `streak_guard` by `missed` (`WHERE qty >= missed`).
      - If user holds `>= missed` cards: consumes `missed` cards, sets `streak = daily_streak + 1` and `guarded = missed`.
      - If user holds `< missed` cards: consumes **0** cards and resets `streak = 1`.

### Payout Calculation Order (Exact)
1. Base + streak (`infra/db/wallet.py:150`):
   `amount = 1000 + 100 * min(streak - 1, 20)`
   (Day 1: `1,000`; Day 2: `1,100`; ...; Day 21+: `3,000`).
2. `daily_double` consumable boost (`infra/db/wallet.py:151-160`):
   - Checks `profile.daily_boost > 0`.
   - If true: `amount *= 2`, decrements `profile.daily_boost` by `1`, sets `boosted = True`.
3. Relic buff (`relic_crown` — `daily` buff key) (`infra/db/wallet.py:161-163`):
   - `amount = round(amount * (1 + relic_buffs.get("daily", 0.0)))` (Python `round()`, banker's rounding; applies AFTER `daily_double`).
4. Teiai debt skim (`infra/db/wallet.py:164-175`):
   - Calls `debt_before = account.debt(gid, user_id)` (accrues daily debt interest first!).
   - If `debt_before > 0`: `skimmed = teiai.skim(amount)` (see `docs/spec/teiai.md` — 20% skim (`skim_rate = 0.20`) on daily while in debt, does NOT reduce debt principal).
   - If `skimmed > 0`: logs a 0-delta ledger row `"帝愛のピンハネ（デイリー {skimmed:,}ペリカ）"` and credits `skimmed` to the Teiai house account (`house_income_for`).
5. Net credit & Teiai debt repayment withholding (`infra/db/wallet.py:175-183`):
   - `credit = amount - skimmed`.
   - Calls `account.apply(gid, user_id, credit, reason, income=credit)`.
   - Ledger reason: `f"デイリー（{streak}日連続{'・2倍券' if boosted else ''}{'・連続守り券' + str(guarded) + '枚' if guarded else ''}）"`.
   - Because `income=credit`, `withhold_income` automatically withholds 30% (`repay_rate = 0.30`) of `credit` toward Teiai debt if in debt (`repaid = debt_before - account.debt(gid, user_id)`).
6. Seed loan top-up (`infra/db/wallet.py:184`):
   - `seed = debt.topup_seed_for(gid, user_id)`: if in debt and cash balance is below the seed threshold, Teiai automatically lends seed money up to the cap (adds to debt).
7. Persistence (`infra/db/wallet.py:185-188`):
   - Updates `users.daily_streak = streak`, `last_daily = today.isoformat()`, `last_slot = slot`.

### Side Effects in Service Layer (`services/economy.py:123-130`)
- On successful claim (`result.ok == True`):
  1. Drains pending notices via `notices.take_notices(user_id)` (NOTE: `EconomyService.claim_daily` drains them without returning them to the embed — notices generated by debt interest/seed are already summarized directly in `DailyResult`).
  2. Rolls for a black-suit earnings insider memo via `earnings.earnings_memo(user_id, now.timestamp())` (see `docs/spec/stocks.md`). If obtained, sent as a separate **ephemeral** followup (`🕴️ 黒服の噂話`).

## State Machine
- Per `(guild_id, user_id)`:
  - `CLAIMABLE` (`slot > last_slot` and `today >= last_daily`) --(`/ペリカ デイリー`)--> `CLAIMED_IN_SLOT` (public embed + optional ephemeral insider memo).
  - `CLAIMED_IN_SLOT` (`slot <= last_slot`) --(`/ペリカ デイリー`)--> `CLAIMED_IN_SLOT` (ephemeral wait embed showing next slot time).
  - `CLAIMED_IN_SLOT` --(clock crosses `00:00`/`06:00`/`12:00`/`18:00`)--> `CLAIMABLE`.

## Edge Cases
- Same-day claims across multiple 6h slots (e.g. 06:00 and 12:00) all pay the full streak amount (and can each consume a stacked `daily_boost` charge), while `streak` stays constant until the next calendar date.
- `next_bonus` displayed in the embed (`embeds.py:93`) uses `min(result.streak, DAILY_STREAK_CAP)` (i.e. tomorrow's base amount assuming streak increments by 1, without `daily_double` or relic buff).
- Seasonal skin active (`skins.active_season(now)`): replaces embed title (without `✅` prefix) and prepends `season.daily_line`; payout numbers are unchanged (`cogs/economy/embeds.py:104-111`).
- First-ever `/ペリカ デイリー` calls `account.ensure` first → grants initial `3,000` Pelica AND then claims Day 1 (`+1,000`), leaving balance `4,000`.
