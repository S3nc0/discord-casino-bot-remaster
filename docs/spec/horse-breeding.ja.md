# 馬の配合 設計（`horse`、新機能）

> 状態：**2026-11-21 にオーナーが承認済み**（§9）。担当：**B2-B** · ゲーム ID：`horse` · 画面 ID：`horse`（厩舎タブ） · 機能トグル：`horse` · 新しい台帳の理由：`horse_breeding_fee`。
>
> 旧 Python には**配合がありません**（[horse.ja.md](horse.ja.md) §1）。ここに書いてあるものは旧版との一致ルールではなく、すべてこの設計独自の数値です。§9 はオーナーの決定の記録、§10 は v1 で見送った案です。

## 1. プレイヤーの体験と、既存の仕組みとの関係

1. *成績のよい馬が 2 頭いる。配合料を払うと、両方に似た子馬が生まれる。少しだけ運も混ざる。*
2. *子馬は 2 日待ってから、ほかの馬と同じように走る：出走、賞金、賭け、32 戦での引退。*
3. *続けていくうちに血統ができ、厩舎に各馬の両親と世代が表示される。*

既存の流れ（[horse.ja.md](horse.ja.md)）との関係：

| 既存の仕組み | 配合を入れたあと |
| --- | --- |
| 所有：`horse_voucher`（30,000）→ 能力 50/50/50/50 の馬、1 人 3 頭まで | 配合は、馬を手に入れる 2 つ目の方法です。上限は同じ 3 頭で、子馬は生まれた時点から 1 枠を使います。 |
| 育成：`carrot`（5 移す）、`gold_carrot`（合計 +10、1 回だけ） | 変わりません。配合が受け継ぐのは**合計**の強さをわずかにだけで、能力の偏りは今までどおり、にんじんで作ります。 |
| レース：JST で 1 日 4〜5 回の通常レース、8 頭立て、1 人 1 レースにつき 1 頭 | 変わりません。子馬は成熟してから走ります。配合しても、オーナーが走らせられる回数は増えません。 |
| 賭け（horse.ja.md §6.2）とオッズ | 変わりません。子馬は 0 戦から始まるので、既存の初出走の係数が適用されます。 |
| 引退：手動、または 32 戦で自動。価値は `clamp(…, −20,000, +60,000)` | 子馬も変わりません。引退した馬は配合できません（§9 D2）。 |

## 2. 配合できる馬

次の条件がすべて満たされた馬が、**配合の対象**です（配合のトランザクションの中で確認します）。

| ルール | 値 |
| --- | --- |
| 配合する本人が所有し、現役である（引退、差し押さえ、プレイヤーマーケットへの出品のいずれでもない） | — |
| 走った回数 | `>= BREED_MIN_RACES = 4`（かつ `< 32`、つまり引退していない） |
| 成熟している（配合で生まれた馬のみ） | `now >= matures_at` |
| これまでに産ませた・産んだ子の数 | `< MAX_FOALS_PER_HORSE = 2` |
| 前回の配合からのクールダウン | `>= BREED_COOLDOWN = 72 h` |

- **組み合わせ：**自分の馬 × 自分の馬で、違う 2 頭です。性別はなく、対象の 2 頭ならどれでも組めます。（3 頭の厩舎では、性別があると使える組み合わせが半分に減り、列、UI の絞り込み、エッジケースが増えるだけで、得るものがありません。）
- **出走は止まりません：**開催前のレースに登録した馬や、クールダウン中の馬も、レースには出られます。配合が触るのは、配合に関わる項目だけです。
- **配合する人の条件：**残高が `>= BREED_FEE`。帝愛の債務が `0` で、破産していないこと（送金する人と同じ立場です。[transfer.ja.md](transfer.ja.md)：債務者は、任意の支出でペリカを外に出せません）。
- **厩舎：**オーナーの馬の頭数（今までどおり、出品中のものを含む）が `< MAX_HORSES = 3`。実際には、両親 2 頭と子馬 1 頭で厩舎がいっぱいになり、もう一度配合するには、引退か売却が必要です。
- **機能トグル：**`horse` が OFF だと新しい配合は止まりますが、すでに生まれた子馬の成熟は進みます。

**v1 に含めないもの：他のプレイヤーの馬を相手にすること（種付け料）。**v1 では見送ることにしました（§9 D1）。将来の案は §10 にあります。

## 3. 子馬

### 3.1 能力（純粋なドメイン関数、`Rng` は注入）

入力：両親の能力 `A`、`B`（各能力は `[20, 80]` の 5 の倍数）。計算はすべて整数で、能力は、にんじんや NPC の能力と同じく、5 の倍数のままです。

1. **合計。**`excess = (sum(A) + sum(B)) / 2 − 200`。`inherit = excess / 2` を、**0 に向かって** 5 の倍数に切り捨てます（`inherit ∈ {−5, 0, +5}`）。ノイズ `n` は `{−10, −5, 0, +5, +10}` から重み `1:2:4:2:1` で選びます。`T = clamp(200 + inherit + n, 190, 210)`。
2. **形。**各能力 `s` について：`t[s] = 50 + ((A[s] + B[s]) / 2 − 50) / 2 + rng.int(−7, 8)`（50 に向かって半分戻し、さらに ±7）。
3. **配分。**すべての能力を 20 から始め、残りの `(T − 80) / 5` 段（1 段 5）を、`max(1, t[s] − 20)` に比例して分けます。端数は大きい順で、同じなら `speed, stamina, power, guts` の順です。80 を超える能力の余った段は、最も低い能力に回します（同じ順番で決めます）。

暴走しない理由：

- **上限：どの馬も、能力の合計が `TOTAL_CAP = 210` を超えてはいけません。**これは現在の最大値（200 + 黄金のにんじん 1 本）です。そのため `gold_carrot` も、使うと合計が 210 を超えるときは失敗します。効くのは `<= 200` の馬だけです。引換券で手に入れた馬と旧版の馬には影響しません（200 + 10 = 210）。
- **平均への回帰：**両親の超過分の半分だけを伝え、200 に向かって切り捨てます。ノイズは対称で、`[190, 210]` の固定は、両親が強いときに、下側より上側を強く削ります。
- 上のルールのシミュレーション（400 頭、50 世代、シード固定の RNG）：ランダムな組み合わせなら、合計の平均は **200.0 ± 0.8** に収まります。常に上位 10% を配合し続けても、平均は **約 204.5** で頭打ちになり（210 を超えません）、各能力は `[35, 70]` にとどまりました。配合で得られるのは、合計でのわずかな優位です。特化した能力の偏りは、今までどおり、にんじんで作ります。

### 3.2 子馬のそのほかの決まり

| 項目 | ルール |
| --- | --- |
| 名前 | 配合のフォームで必須です。引換券の馬と同じルール（horse.ja.md §2.1：1〜12 文字、使えない文字、`http` 禁止）。 |
| 毛色 | 45% は親 A、45% は親 B、10% は `COATS` からの一様な抽選。 |
| 勝負服 | フォームで配合する人が選びます（既定は親 A）。あとから今までどおり変えられます。 |
| 脚質 | `None`（自動）。 |
| 戦績 | `races = wins = places = 0`。成熟の間も、にんじんと黄金のにんじんを使えます。 |
| 成熟 | `matures_at = foaled_at + FOAL_MATURITY = 48 h`（通常レースの約 9 回分）。それまでは出走登録ができません。プレイヤーマーケットでの取引はできます。 |
| 世代 | `max(gen(A), gen(B)) + 1`。引換券、差し押さえ、旧版の馬は世代 0 です。 |
| 基準価値 | `base_value = BREED_FEE`（15,000）。引換券の 30,000 ではありません。旧版が馬 1 頭につき `30,000` を使う箇所で使います：資産の評価 `max(0, base_value + retire_value)`、破産時の差し押さえの入金、帝愛オークションの価格。「15,000 で配合して 30,000 に数える」ことを防ぎます。 |

配合は**即時**です。1 つのトランザクションで、配合料の徴収、両親の更新、子馬の作成を行います。妊娠の状態もスケジューラーのジョブもありません。

## 4. 経済

| 定数 | 値 | 流れ |
| --- | --- | --- |
| `BREED_FEE` | **15,000** ペリカ（引換券の半額） | `horse_breeding_fee`、**シンク** |
| 新しい供給源 | **なし** | — |

horse.ja.md と、初期残高 3,000 に照らした規模感：

- 新規プレイヤー（3,000）は配合できません。配合する人は、引換券 2 枚で 60,000 を払い済みで、それぞれ 4 戦走っています。15,000 は、満員のレースの 1 着賞金（12,000）の約 1¼ 回分（プールの調整で通常はもっと少なく、実際には数回の勝利が必要）、またはデイリーボーナスの 1〜4 日分（1 回 1,000〜3,000、1 日 4 回）にあたります。
- 引換券（30,000）より安いのは、やる価値を持たせるためです。ただし無料ではなく、厩舎の 1 枠と、48 時間 + 72 時間の待ちがかかります。

インフレの確認（サーバーごと）：

1. **馬に関する唯一の供給源は、引退の払い出しです**（`horse_retirement`、32 戦で最大 +60,000）。その頻度は、馬の頭数ではなく、レースの枠で決まります。1 人 1 レースにつき 1 頭、1 日約 4.5 レース ⇒ オーナー 1 人につき、32 戦のキャリアは約 7 日に 1 つが上限です。**配合してもこの上限は変わりません。**
2. **平均的な馬は、純粋なシンクです。**フィールドの平均（勝率 1/8、3 着以内 3/8）なら、32 戦のキャリアは `4×5,000 + 8×2,000 − 20×2,000 = −4,000`（手数料）で終わります。出走料（32 × 1,000）が賞金プール（賞金は `real_entries × 1,000` に比例）をほぼまかなうため、ループは閉じています。平均的な子馬 1 頭あたり：`−15,000` の配合料と `−4,000` の引退で、約 **−19,000** ペリカが流通から出ていきます。
3. **最悪のケース：**配合は 30,000 の引換券のシンクを 15,000 に置き換えるので、代替の馬 1 頭あたり、シンクは最大で **15,000 減ります**。オーナー 1 人につき週に 1 頭以下の置き換え ⇒ 1 日あたり、オーナー 1 人につき約 2,100 ペリカ以下です。デイリーボーナスの供給（プレイヤー 1 人あたり 1 日 4,000〜12,000）に比べれば小さく、それでもシンクです。
4. **ランキング：**`純資産`（既定のランキング）には馬を含めません。`総資産` は子馬を `base_value` の 15,000（払った価格）で数えるため、配合でかさ上げすることはできません。

## 6. エッジケース

| ケース | 挙動 |
| --- | --- |
| クールダウン中に親が引退した | 何もしません。クールダウンは馬の行に持たせてあるので、子馬と血統には影響しません。 |
| クールダウン中に親を売った・取引した | `last_bred_at` と `foal_count` は馬について回るので、買った人がクールダウンと、残りの子の枠を引き継ぎます（友達に売ってもリセットされません）。 |
| 親がマーケットに出品中 | 出品中は対象外です（オーナー `-3`）。トランザクション内の所有の確認が、`conflict` で失敗します。 |
| 破産（自己破産、強制、逃亡） | 子馬も、ほかの馬と同じように差し押さえられます（オーナー `-1`）。成熟前の子馬も同様で、成熟のカウントは続きます。差し押さえの入金と帝愛オークションの価格には `base_value` を使います。 |
| 配合する人が債務中／破産猶予中／破産者 | 何も変えずに拒否します（`horse.breed.err.in_debt`）。残高はマイナスになりません。配合料は現金でまかなう必要があります。 |
| 確認とコミットの間に債務ができた | トランザクションが債務と残高を読み直し、完全にコミットするか、何も変えないかのどちらかです。 |
| 厩舎が上限 | 課金の前に拒否します（`stable_full`）。マーケットの出品も、今までどおり数えます。プレイヤーマーケットのオークションで落札した場合も、精算時に買い手の上限を確認します（player-market.ja.md）。 |
| オーナーがサーバーを抜けた | こちらからは見えません（メンバーインテントがないため）。馬はその場に残り、実質的に凍結されます（オーナーなしでは出走登録ができません）。戻ってくればすべて残っています。 |
| 同じ親を使った 2 つの配合リクエスト（ダブルクリック、2 台の端末） | `idempotencyKey` が同じなら、保存済みのレスポンスを再生します。違うキーなら、SQLite が書き込みを直列化します。親の更新は条件つきで（`WHERE last_bred_at IS NULL OR last_bred_at <= now − 72 h AND foal_count < 2`）、両方の行が変わる必要があり、そうでなければ `conflict` でロールバックします。 |
| 親のレースの精算中に配合する | 衝突しません。精算は戦績を、配合は配合の項目を書きます。先に親が 32 戦で自動引退したなら、配合は対象外になって失敗します。 |
| 振り直しの試み | 能力はサーバーで 1 回だけ抽選し、同じトランザクションで保存します。再生しても、保存済みの子馬が返ります。支払う前のプレビューはありません。0 戦の子馬を引退させても、払い出しは 0 です。 |
| 機能 `horse` を OFF にした | 新しい配合は止まり、子馬の成熟は進み、既存のデータには触れません。 |

## 7. 実装の概要（B2-B 向け）

- レースのドメインモジュール（`packages/domain/race/`、B2-B）に、純粋な `breedFoal({ a, b, name, silks }, ctx)` を置きます：対象の確認、能力（§3.1）、毛色。子馬の下書きと `HorseFoaled` イベントの下書きを持つ `Outcome` を返します。定数は、馬のカタログの隣のカタログのブロックに置きます。
- サーバーのサービス：1 つのトランザクション ＝ 両方の馬と配合する人（残高、債務、頭数）の読み直し、条件つきの親の更新、`EconomyService` による `horse_breeding_fee` の引き落とし、子馬と `horse_breedings` の挿入、冪等性の記録。コミットのあとに `HorseFoaled` を発行します。
- 出走登録：既存の登録の確認の隣に `matures_at` の確認を足します。`gold_carrot`：`TOTAL_CAP` の確認を足します。
- 共有部分の変更（先に A1 のタスク）：台帳の理由、`HorseFoaled`、通知の種類 `horse_foaled`、i18n キー。

## 8. テスト計画

プロパティテスト（シード固定の RNG、多数回）：

- 有効な任意の 2 頭の親（能力が `[20, 80]` の 5 の倍数、合計が `[190, 210]`）について：子馬の能力は `[20, 80]` の 5 の倍数で、合計は `[190, 210]` かつ `<= TOTAL_CAP`。
- **上向きのドリフトがない：**400 頭の集団でランダムに組み合わせて 50 世代続けても、合計の平均は `200 ± 2`、各能力の平均は `50 ± 2` に収まります。
- **選抜しても頭打ち：**常に合計の上位 10% を配合しても、210 を超える合計は出ず、平均は `<= 206` にとどまります。
- 同じシードと同じ両親からは同じ子馬が生まれます（決定論）。親 A と B を入れ替えても、合計の分布は同じです。

単体のケース：

- 対象のルールが、それぞれ単独で拒否すること：3 戦、クールダウン 71 時間 59 分、`foal_count = 2`、成熟前の子馬を親にする、同じ馬を 2 回、他のプレイヤーの馬、引退、出品中、差し押さえ。
- 配合料：残高がちょうど 15,000 なら成功して 0 になる。14,999 なら、行を書かずに失敗する。債務 `> 0` なら失敗する。
- 厩舎：3 頭（または 2 頭 + 出品 1 件）なら失敗する。2 頭なら成功して 3 頭になる。
- 台帳：`−15,000` の `horse_breeding_fee` が 1 行。`isDeltaAllowed` が成り立つ。`ref_id` ＝ 配合の ID。供給量のチェックもつり合うこと。
- 冪等性：同じキーを 2 回 → 子馬 1 頭、台帳 1 行、`replayed: true`。1 頭の親に 2 つの別のキーが競合 → 子馬はちょうど 1 頭。
- 子馬：世代、`matures_at = foaled_at + 48 h`、`base_value = 15,000`。出走登録は 47 時間 59 分で拒否され、48 時間で受理される。
- 黄金のにんじんは、合計 205 の子馬には失敗し、合計 200 の子馬には成功して 210 になる。
- 破産で、成熟前の子馬も差し押さえられる。評価額とオークション価格は 15,000 を使う。

## 9. 決定事項（2026-11-21）

オーナーは、すべての推奨を受け入れました。

- **D1 組み合わせ：**自分の馬 × 自分の馬のみ。v1 では、種付け料や、オーナーをまたぐ配合はありません。
- **D2 引退した馬：**配合できません。対象は現役の馬だけです。
- **D3 配合料：**`BREED_FEE = 15,000` ペリカ（シンク）。
- **D4 厩舎の上限：**`MAX_HORSES = 3` のまま。子馬も含みます。
- **D5 合計の上限：**すべての馬の能力の合計に `TOTAL_CAP = 210`。`gold_carrot` は、使うと 210 を超えるなら失敗します。

## 10. 将来の案（v1 には含めない）

**種付けのオファー（他のプレイヤーの馬を相手にする）。**あとで欲しくなったとき、いちばん単純な形は、_常設のオファー_です。種馬のオーナーが、対象の馬 1 頭を、`[1,000, 30,000]` の `STUD_FEE` で「種付け可」にします。ほかのプレイヤーは、自分の対象の馬 1 頭をそれと即座に組み合わせ、1 つのトランザクションで `BREED_FEE`（シンク）と `STUD_FEE`（送金）を払います。そのためエスクローは要りません。子馬は配合した人のものになり、種馬にはクールダウンと子の数が加わります。オファーは 7 日で失効し、種馬が引退、売却、出品、差し押さえになったときに取り下げられます（破産で削除されます）。

- 台帳：送金の理由は符号が 1 つに固定なので、ペアにします：`horse_stud_fee`（送金、−1、`競馬:種付け料（{stud}）`）と `horse_stud_income`（送金、+1、`競馬:種付け料の受け取り（{stud}）`）。種付け料の収入には、いつもの 30% の `debt_withholding` の行が付きます。
- データ：`horse_stud_offers (guild_id, horse_id PK with guild, owner_id, fee, created_at, expires_at)`。`horse_breedings` に `stud_owner_id NULL`、`stud_fee NULL` を足します。種馬のオーナーの受信箱のために、`HorseFoaled` に任意の `studOwnerId` を足します。配合のインテントに `studOfferId` を足します。
- 経済：送金の行は合計が 0 になります。この方法で友達にペリカを移すと、毎回 15,000 のシンクがかかり、`/送金` の 10% の手数料よりずっと高くつくので、送金の上限を迂回する手段にはなりません。
- リクエストごとに承認する方式にするなら、代わりにエスクローの預かりと解除のペアと、保留中の状態が必要になります。オーナーが相手を選びたいと望むときだけ、やる価値があります。
- テスト：種付けの行の合計が 0 になること。債務のあるオーナーへの種付け料の収入が `debt_withholding` を生むこと。失効または取り下げ済みのオファーは `conflict` になること。

**種牡馬として引退させる**（D2 の代替案）：払い出しなしで、引退した馬を繁殖用に残します。上限には数えます。
